## Посмотреть результат

Откройте `dataset-review.html` в браузере двойным щелчком. Он работает локально, без сервера и загрузки видео в интернет. Есть фильтры по классу, поиск, замедление, переход к действию и ссылки на исходник с таймкодом. Сами клипы находятся в `videos/clips/`, по папкам классов.

Страница предназначена для просмотра и не сохраняет правки. Для v2 есть отдельный фильтр, прежние метки и границы, объяснения правок и дополнительные кадры. Решения v2 находятся в `data/reviews/annotation-v2.json` и применяются поверх исходных `data/review_decisions.json` и HF-разметки. После правок нужно пересобрать индекс, экспорт v2 и разбиение; команды — в [описании ревизии](docs/annotation-v2.md).

Если браузер не открывает локальное видео, запустите из корня проекта `python scripts/serve_review.py` и откройте `http://127.0.0.1:8765/dataset-review.html`. Этот сервер поддерживает HTTP Range для перемотки видео и доступен только на вашем компьютере. Остановить его можно через Ctrl+C.

## Что означают метки

- **Пас пяткой:** передача мяча партнёру пяткой. Удары пяткой, ведение мяча и передачи плечом сюда не входят.
- **Удар через себя:** удар в прыжке с отклонением назад или боковые «ножницы». Оба вида включены по решению пользователя.
- **Other:** обычные передачи, удары, верховая борьба, ведение, подкаты, стандартные положения и паузы, а также несколько похожих действий из исходных сборников: удар пяткой, финт и передача плечом.
- **Uncertain:** техническая очередь проверки. Не использовать как четвёртый класс и не переименовывать автоматически в `other`: здесь могут быть целевые действия.

## Как получены таймкоды

Сборники визуально просмотрены через обзорные листы кадров с шагом 2 секунды и подробные последовательности с шагом 0,5 секунды вокруг выбранных эпизодов. Окна подобраны по этим кадрам с контекстом до и после действия. Это выборочная разметка эпизодов, а не покадровая разметка всего матча; отдельные действия могли быть пропущены.

Все метки имеют статус `provisional`, а проверка человеком — `pending`. В v2 повторно просмотрены 49 клипов по кадрам через 0,125 секунды; для остальных сохраняется исходная проверка через 0,5 секунды. `action_sec` — приблизительное время контакта/действия. Десятичные знаки не означают покадровую точность; в двух спорных клипах неподтверждённая точка действия снята. Для коротких монтажных вставок контекст ограничен; это отмечено полем `short_context`.

Для HF просмотрены последовательности кадров первых 12 секунд каждого из 40 выбранных роликов с шагом 0,5 секунды. Из них вручную выбраны 108 трёхсекундных окон. Это предварительная проверка по кадрам, а не непрерывный просмотр всех исходных роликов. Точное время целевого действия для фона не задаётся: `action_sec` и `action_offset_sec` равны `null`.

В некоторых клипах остаётся склейка ракурсов или замедление, уже присутствующие в сборнике. Не все повторы экспортированы. В v2 добавлены две заставки и четыре празднования как отрицательные примеры. Кандидат № 97 из `smNANjh2t2Q` пропущен: он повторял конец предыдущего эпизода.

Имена игроков и команд в примечаниях служат навигации по видео; это не проверенная база идентичностей игроков.

## Файлы

- `data/sources.json` — четыре источника, YouTube ID, длительность, разрешение, FPS и SHA-256 исходных файлов.
- `data/annotations.json` — основной индекс: метка, путь клипа, исходный ролик, границы в секундах, время действия, группа повторов и статус проверки.
- `data/review_decisions.json` — редактируемые решения: `[номер, начало, конец, время_действия, метка, примечание, необязательная_общая_группа]`. Секунды относятся к исходному файлу.
- `data/seeds.json` — центры подробных последовательностей кадров; вспомогательный материал разметки.
- `data/dataset_summary.json` — актуальные количества после сборки индекса.
- `data/validation.json` — результат технической проверки каждого экспортированного клипа; создаётся командой `validate`.
- `data/other_annotations.json` — отрицательные примеры HF, исходники, группы матчей и закреплённые части выборки.
- `data/external/infactory-soccer-events/` — снимок метаданных источника, версия, отбор и решения по просмотренным окнам.
- `videos/review/` — обзорные листы и кадры вокруг эпизодов.
- `scripts/video_dataset.py` — извлечение кадров, нарезка и проверка видео.
- `scripts/build_annotations.py` — сборка индекса и локальной страницы просмотра.
- `scripts/prepare_other.py` — загрузка выбранной части HF, кадры для проверки, сборка и экспорт `other`.

Исходные видео сохранены. Имеющееся имя папки `videos/bycicle_kick/` оставлено; в разметке используется правильная метка `bicycle_kick`.

## Повторить нарезку

Нужен Python 3.11 или новее. Например, в PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-data.txt
.\.venv\Scripts\python.exe scripts/build_annotations.py
.\.venv\Scripts\python.exe scripts/video_dataset.py export --revision v2
.\.venv\Scripts\python.exe scripts/split_dataset.py
.\.venv\Scripts\python.exe scripts/video_dataset.py validate
```

FFmpeg поставляется с `imageio-ffmpeg`. Можно указать другой исполняемый файл через переменную `FFMPEG_BINARY`. Для текущей первой нарезки использован Python среды Codex, а локальная копия `imageio-ffmpeg` установлена в игнорируемую папку `.tools/python`.

Экспорт создаёт H.264 MP4 в исходном разрешении 1280×720, без звука, с CRF 18. FPS берётся из источника. Границы получаются перекодированием. `export --revision v2` записывает 55 пересмотренных и добавленных клипов по путям `videos/clips/v2/`. Остальные пути используют прежние файлы. Ориентируйтесь на индекс: обход всех папок MP4 захватит старую и новую версии. `export` без фильтра перезапишет все файлы текущего индекса.

Пример получения дополнительных кадров:

```powershell
.\.venv\Scripts\python.exe scripts/video_dataset.py sheets aVL9JkMTbV8 --start 5 --end 10 --step 0.25
```

## Перед обучением

1. Проверить метки и границы через страницу просмотра. Особенно просмотреть `uncertain` и короткие вставки.
2. Проверить новые `other`, особенно передачи и борьбу, на отсутствие коротких целевых действий между просмотренными кадрами. Продолжать добавлять отрицательные и положительные примеры из одинаковых источников: иначе модель может узнавать стиль трансляции или водяной знак.
3. Завершить проверку совпадений между сборниками и по возможности добавить независимые матчи для оценки. Уже подготовлено экспериментальное разбиение ниже: тестовые исходники отделены, известные совпадения исключены из обучения. Полная независимость матчей ещё не подтверждена.

`training_candidate = true` означает лишь, что метка не спорная и это первый выбранный представитель известной группы. Это **не автоматическое одобрение качества** и не готовое разбиение для обучения. Четыре сборника с монтажом, замедлениями и узнаваемыми игроками пока не показывают, как модель будет работать на обычных записях матчей. Для распознавания самого удара через себя понадобятся также промахи и заблокированные удары, поскольку текущие сборники в основном показывают голы.

Подготовка данных сама по себе не обучает модель: для этого служит отдельный модуль `socspot.train`, описанный в [инструкции запуска](docs/running.md). Большие видео, веса, кадры, локальные зависимости и виртуальное окружение исключены из Git; JSON-разметку, отчёты и скрипты можно хранить в репозитории.

## Train, validation и test

Текущее разбиение v2 хранится в `data/splits/review_v2_source_holdout/`: `train.json`, `validation.json`, `test.json`, `excluded.json` и `summary.json`. Первоначальное `data/splits/initial_source_holdout/` сохранено для воспроизведения первого эксперимента. Это списки путей к уже нарезанным клипам; видео не копируются.

| Часть | Пас пяткой | Удар через себя | Other | Всего |
|---|---:|---:|---:|---:|
| Train — обучение весов | 81 | 44 | 79 | 204 |
| Validation — выбор настроек и порогов | 21 | 10 | 18 | 49 |
| Test — пересмотренный известный набор | 45 | 25 | 22 | 92 |

Для test отложены исходники `aVL9JkMTbV8` и `S-484NrAYuw`. Train и validation используют `smNANjh2t2Q` и `oA2pyZULjiM`. Если известный эпизод есть в тестовом сборнике, его представление из обучающего сборника исключается. В каждой известной группе повторов выбирается один клип. В итоге исключены 9 спорных фрагментов и 23 повтора, включая 7 повторов тестовых эпизодов в обучающих источниках. Отрицательные окна празднований связаны с соответствующими ударами для разбиения.

Из HF добавлены 76 клипов из 28 матчей в train, 16 из 6 матчей в validation и 16 из 6 матчей в test. Все окна одного матча остаются вместе. Распределение ранее выбранных клипов сохранено.

Результат воспроизводится командой `python scripts/split_dataset.py`. Настройки v2 — `data/split_config_v2.json`. Скрипт проверяет учёт всех клипов, существование файлов, непересечение известных событий и сохранение прежних частей для существующих групп. Хеши разметки, настроек и исходного разбиения записываются в манифесты. Новые группы распределяются воспроизводимо, связанные окна остаются вместе.

**Test уже использовался при оценке v1.** Исправление его меток и состава не создаёт новый независимый тест. Метрики v1 и будущей v2 нельзя напрямую сравнивать как доказательство улучшения: изменились и правила класса, и количество примеров. Для следующей независимой оценки нужны новые записи.

**Это предварительное разбиение.** Train и validation целевых классов используют те же два сборника; тест использует другие два, но невыявленные повторы и общие матчи всё ещё возможны. Для HF пересечения матчей между частями исключены по метаданным. Пересечения HF с исходными сборниками полностью не проверены. Оценка на этих клипах ещё не показывает качество поиска событий в полном матче.

Для исходных четырёх сборников `data/annotations.json` сохраняет консервативную группировку: `split = null`, `split_group = initial_four_compilations`. Эксперимент использует предварительные `event_id` и помечен `experimental`. У HF заданы `split`, `match_id` и `evaluation_group` по матчу. Состав частей определяется манифестами; признаки `training_candidate` и `duplicate_of` не заменяют эти списки.

## Источник other и повторение импорта

Использован [infactory-ai/soccer-events](https://huggingface.co/datasets/infactory-ai/soccer-events), версия `d8ba9a491eea5c573525a37d42fd55144c12dd37`. Скачаны 40 роликов — около 1,10 ГиБ. Полный датасет не загружался. Выбран один ролик на матч: 30 с исходной меткой гола и 10 с меткой карточки; метка источника служила только для отбора кандидатов, а `other` назначен отдельным просмотренным окнам.

В исходном индексе есть `Back Heel` и `Overhead/Bicycle`. Матчи с этими метками исключены из отбора отрицательных примеров. Это не доказывает отсутствие других неразмеченных целевых действий.

В карточке источника указано **только некоммерческое исследовательское использование**. Это ограничение записано в манифестах и относится к использованию этого дополнения. HF-видео имеют 15 FPS и водяной знак Infactory; при обучении нужно учитывать риск распознавания источника вместо действия.

```powershell
python scripts/prepare_other.py download
python scripts/prepare_other.py evidence
# После проверки или правки data/external/infactory-soccer-events/review_decisions.json:
python scripts/prepare_other.py build
python scripts/prepare_other.py export
python scripts/build_annotations.py
python scripts/split_dataset.py
python scripts/video_dataset.py validate
```

`selection.json` фиксирует скачиваемые источники, их ревизию и распределение матчей. Команда `plan` пересоздаёт этот отбор из сохранённого индекса; для обычного повторного запуска она не нужна. MP4 и кадры исключены из Git. Список источников, хеши, разметка и скрипты сохраняются в репозитории.

## Проверка нарезки

Все 377 клипов полностью декодированы без ошибок. Проверены разрешение, FPS, существование ссылок на кадры и соответствие длительности границам; максимальное расхождение — 0,04 секунды. SHA-256 всех 44 исходников совпадает с описью. Размер файлов текущего индекса — около 505 МиБ. Результаты записаны в `data/validation.json`. После обучения v2 контрольные суммы 385 файлов первого эксперимента, включая прежние клипы, веса, отчёты и разбиение, не изменились; `models/current.json` намеренно переключён на v2.

При первой нарезке в браузере отдельно проверены загрузка и воспроизведение видео, фильтры классов, поиск, переключение клипов, пустая выдача, скорость 0,5× и переход к действию. Для HTTP-просмотра проверена перемотка через сервер `serve_review.py`. После добавления HF проверены обновлённые счётчики, поиск новых клипов, загрузка трёхсекундного видео и отключение кнопки «К действию» для фоновых окон без точки действия. Для v2 отдельно проверены фильтр 55 изменённых/новых клипов, поиск, загрузка новых видео, прежние метки и границы, переход к действию и отключение перехода у спорного клипа без подтверждённой точки. Эти проверки подтверждают работу файлов и просмотра; качество семантических меток остаётся предварительным.
